# Фракции

## Модель

У агента есть **принадлежность** к фракции. Враждебность — правило между фракциями, а не метка «враг» на агенте.

- `FactionDefinition` (ScriptableObject, `Configs/Gameplay/Factions/`) — список `_hostileTo`. `IsHostileTo(other)` проверяет, есть ли другая фракция в этом списке. Отношения могут быть несимметричными; обычно их задают с обеих сторон.
- `FactionTrait` (`IAgentTrait`, поле `_faction`) → компонент `Faction { FactionDefinition Value }`.
- `FactionRelations` — расширения для `Stash<Faction>`:
  - `AreHostile(source, target)` — у обоих есть фракция, и фракция источника враждебна фракции цели;
  - `HasFactions(source, target)` — у обоих есть фракция.

Сейчас заведены две фракции: `Player` и `Monsters`, враждебные друг другу.

## Где проверяется

| Место | Правило |
|---|---|
| `FactionDamageFilterSystem` (группа Damage, после `DamageImmunity`, до `DamageApply`) | Если у источника и цели есть фракции, а враждебности нет — событие урона удаляется. Урон без фракций (окружение, ловушки) проходит |
| `PerceptionSystem` | Воспринимающий агент должен иметь `Faction`. Цели — сущности с `Faction`, враждебные ему, без `Dead` |

Попадание остаётся физическим: союзник на пути удара блокирует сферу, но урона не получает.

Маска слоёв в `MeleeHitTrait` больше не отвечает за выбор целей. Оба оружия используют «всё, кроме `Ignore Raycast`».

## Точки расширения

- Новая фракция — новый ассет, без кода. Например, нежить, враждебная зверям: монстры начнут драться между собой.
- Агрессия в ответ на удар (нейтральный зверь нападает) — компонент-исключение вроде `HostileOverride { Entity }`, который учитывают обе проверки.
- Динамические отношения (стража после преступления) — перенести отношения из ассета в рантайм-состояние. Проверки в системах останутся теми же.
- Дружественный огонь — убрать фильтр или заменить его модификатором урона.
